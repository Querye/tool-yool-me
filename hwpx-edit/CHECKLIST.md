# HWPX 편집기 — 결과 파일 확인 체크리스트

브라우저 쪽 동작은 자동 시험으로 확인했지만, **한글(HWP) 프로그램이 결과 파일을
군말 없이 여는지는 한글이 깔린 Windows 에서 직접 확인해야 한다.**
아래 순서대로 한 번만 해 두면 이후로는 믿고 쓸 수 있다.

## 0. 준비

- Windows + 한글 2018 이상 (HWPX 는 한글 2014 부터 지원)
- 시험 파일은 **실제 업무에서 쓰는 HWPX 사본**으로 한다.
  도구 안의 `샘플 HWPX 만들기` 로 만든 파일은 손으로 짜 맞춘 최소 구성이라
  한글이 안 열 수도 있다. 샘플이 안 열리는 것과 편집기가 고장 난 것은 다른 문제다.
- 원본은 절대 덮어쓰지 않는다. 결과는 항상 `이름_수정.hwpx` 로 따로 저장된다.

## 1. 원본이 먼저 HWPX 인지

- [ ] 파일 확장자가 `.hwpx` 다. `.hwp` 는 구조가 완전히 다르므로
      한글에서 `다른 이름으로 저장 → 한글 문서 (*.hwpx)` 로 바꾼 뒤 쓴다.
- [ ] 편집기에 올렸을 때 `섹션 n개 / 문단 n개` 통계가 뜬다.
      (0 이거나 오류가 나면 그 파일은 이 도구로 다룰 수 없다)

## 2. 여는 순간

- [ ] 한글에서 결과 파일이 **복구 안내창 없이** 바로 열린다.
- [ ] "파일이 손상되었습니다" / "형식이 올바르지 않습니다" 가 뜨지 않는다.
- [ ] 문서 제목·쪽 번호·머리말/꼬리말이 원본과 같다.

## 3. 바꾼 내용

- [ ] `{{치환자}}` 자리에 넣은 값이 그대로 들어갔다.
- [ ] 채우지 않고 비워 둔 치환자는 `{{...}}` 모양 그대로 남아 있다.
- [ ] 찾아바꾸기한 낱말이 문서 전체에서 바뀌었다.
- [ ] 표 안의 셀 값이 의도대로 바뀌었다.

## 4. 바꾸지 않은 것이 그대로인지 — 여기가 제일 중요하다

- [ ] 글꼴·글자 크기·굵기·색이 원본과 같다.
- [ ] 문단 정렬, 줄 간격, 들여쓰기가 흐트러지지 않았다.
- [ ] 표의 선 모양·셀 병합·칸 너비가 그대로다.
- [ ] 그림·도장·서명 이미지가 제자리에 있다.
- [ ] 쪽 나눔 위치가 밀리지 않았다. (글자 수가 늘면 자연히 밀릴 수 있다)
- [ ] 각주·미주·메모가 남아 있다.
- [ ] 머리말/꼬리말, 쪽 번호가 살아 있다.

## 5. 한글 특수 입력 시험

아래 값을 치환자에 넣어 저장한 뒤, 한글에서 그대로 보이는지 본다.

| 넣는 값 | 확인할 점 |
|---|---|
| `○○시청 ㈜ ℃ ※ 「」 ▶` | 특수문자가 깨지지 않는다 |
| `A & B < C > D` | `&`, `<`, `>` 가 글자 그대로 보인다 (XML 이스케이프) |
| `첫째 줄`+Enter+`둘째 줄` | 한 문단 안에서 줄이 바뀐다 (Shift+Enter 와 같은 줄바꿈) |
| 공백 한 칸 | 원래 글자가 지워지고 빈칸이 된다 |
| (아무것도 안 넣음) | 그 치환자는 손대지 않는다 |
| 아주 긴 문장 | 줄이 넘어가되 서식이 깨지지 않는다 |

## 6. 되돌려 넣기 시험

- [ ] 결과 파일(`_수정.hwpx`)을 **편집기에 다시 올린다.**
- [ ] 통계의 `섹션/문단/표` 개수가 처음과 **똑같다.**
      (숫자가 달라졌다면 구조가 바뀐 것이므로 그 파일은 쓰지 않는다)
- [ ] 채운 치환자는 목록에서 사라지고, 안 채운 것만 남아 있다.

## 7. 한글에서 한 번 더 저장

- [ ] 결과 파일을 한글에서 열어 `저장`을 누른다. 경고 없이 저장된다.
- [ ] 다시 열어도 내용이 그대로다.
  (한글이 자기 형식으로 다시 써 주므로, 이후로는 완전히 정상 파일이 된다)

## 문제가 생겼을 때 원인 좁히기

| 증상 | 볼 곳 |
|---|---|
| 한글이 "손상된 파일" 이라고 함 | 원본을 **아무것도 고치지 않고** 그냥 저장만 해서 열어 본다. 그것도 안 열리면 재압축 문제, 열리면 치환 문제다. |
| 바꾼 글자만 서식이 다름 | 치환자가 여러 `hp:run` 에 걸쳐 있던 경우다. 바뀐 글자는 **맨 앞 run 의 서식**을 따라간다. 한글에서 그 부분만 서식을 다시 잡아 주면 된다. |
| 치환자가 목록에 안 뜸 | 중간에 줄바꿈(Shift+Enter)이나 탭이 끼어 있으면 일부러 건너뛴다. 한글에서 `{{키}}` 를 지우고 한 번에 다시 입력한다. |
| 표 셀에 값이 안 들어감 | 저장 메시지에 `표 셀 n곳은 넣지 못했습니다` 가 뜬다. 글자를 담을 구조가 없는 셀이다. 한글에서 그 셀에 아무 글자나 한 번 넣고 저장한 뒤 다시 시도한다. |
| 미리보기 텍스트가 옛날 내용 | `Preview/PrvText.txt` 는 일부러 건드리지 않는다. 한글에서 한 번 저장하면 새로 만들어진다. 문서 내용에는 영향이 없다. |

## 만든 방식 (고칠 때 참고)

- `hwpx-edit/index.html` 한 파일로 끝난다. 빌드 없음, 외부 CDN 없음.
  JSZip 3.10.2 를 파일 안에 그대로 넣어 두었다 (망분리 환경 대비).
- 건드리는 파일은 `Contents/section*.xml` 뿐이고, 그 안에서도 `<hp:t>` 의
  텍스트 노드만 바꾼다. 나머지 파일과 손대지 않은 섹션은 원본 바이트 그대로 다시 넣는다.
- 재압축할 때 `mimetype` 은 맨 앞·무압축(STORE), 나머지 항목은 원본 ZIP 의
  순서와 폴더 항목 구성을 그대로 따라간다.
- XML 선언부와 BOM 은 루트 엘리먼트 앞 문자열을 통째로 떼어 두었다가 다시 붙인다.
  (`XMLSerializer` 는 선언을 안 써 주고, 기본 `TextDecoder` 는 BOM 을 지운다)
